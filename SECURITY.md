# Security Policy

## Reporting a Vulnerability

If you believe you've found a security vulnerability in any StackSaga module, **please do not open a public issue or discussion**. Public disclosure before a fix is available puts every StackSaga user at risk.

Instead, report it privately using **[GitHub Security Advisories](../../security/advisories/new)**:

1. Go to the **Security** tab of this repository.
2. Click **"Report a vulnerability"**.
3. Provide as much detail as possible: affected module and version(s), a description of the vulnerability, potential impact, and — if possible — steps to reproduce it.

We will acknowledge your report and work with you privately to understand and address the issue before any public disclosure.

## Response Times

- **Community (free) users:** We investigate and respond to reported vulnerabilities on a **best-effort basis**. No fixed SLA applies.
- **Commercial support subscribers:** Security reports receive **prioritized handling** as part of your subscription. Contact **[LICENSING_CONTACT_EMAIL]** if you hold a commercial support subscription and need to escalate a report.

## Supported Versions

Security fixes are generally provided for the latest released version of each module. Older versions may not receive backported patches under the free community license; commercial support subscribers can request extended coverage.

We nonetheless take security reports seriously and encourage responsible disclosure through the process above. Security patches and remediation with a guaranteed response are available exclusively through a paid commercial support subscription — see [README.md](./README.md#-support) for details.

## Disclosure Policy

We follow a coordinated disclosure approach: once a fix is available (or a reasonable amount of time has passed), we will publish a security advisory crediting the reporter (unless anonymity is requested).
